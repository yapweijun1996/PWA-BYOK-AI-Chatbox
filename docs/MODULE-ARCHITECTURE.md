# Module boundaries

Luma Chat is a browser-first application. Keep persisted formats, provider transcripts, and active-branch isolation compatible when moving code across these boundaries.

- `App.tsx` composes the workspace. `components/MessageList.tsx` and `components/SettingsView.tsx` own the corresponding views; message and reasoning styles live in `message-list.css` and `reasoning.css`.
- `workspace-session.ts` owns the in-memory workspace snapshot. `workspace-state.ts` connects it to React. `use-conversation-persistence.ts` serializes conversation writes and tracks drafts; `workspace-conversations.ts` coordinates navigation, branch-aware search, organization and conflict recovery through that same queue. `use-conversation-scroll.ts` owns scroll-follow behavior. The workspace coordinator supplies the active session and UI decisions.
- `reply-runner.ts` owns an in-flight reply's streaming, tool continuation, checkpoints and finalization. Its dependencies are explicit; the coordinator supplies the current session, persistence and provider observation functions.
- `workspace-message-actions.ts` coordinates sending, retrying, editing and branch changes around durable conversation writes. `workspace-clear.ts` retires asynchronous work and waits for pending writes before clearing local data; the UI is reset only after the storage transaction succeeds.
- `use-settings-persistence.ts` owns the serialized settings write queue and reconciles optimistic edits against cross-tab conflicts. `use-model-catalog.ts` derives the visible model choices, while `workspace-model-actions.ts` coordinates selection, capabilities, catalog discovery and provider status without bypassing the settings queue or destination-bound credentials.
- `use-credential-state.ts` owns session credentials and provider form state. `credential-manager.ts` restores device vaults and manages save/delete actions through injected settings writes and cancellation. Credentials remain bound to their provider destination; legacy vaults are not automatically restored.
- `backup.ts` validates and prepares portable backups. `use-backup-state.ts` owns preview state; `backup-actions.ts` coordinates file selection and the atomic IndexedDB import, while `backup-import-plan.ts` builds a transaction after checking the preview against the latest workspace. Import preserves local vaults and does not carry cloud-history consent across devices.
- `provider-adapters.ts` defines the common model discovery and streaming contract and registers every `ProviderId`; `providers.ts` keeps the existing application-facing functions and dispatches through that contract. `provider-transport.ts` owns authenticated fetches, endpoint policy and HTTP errors, with transport injected into the adapter registry for testing. Credentials and cancellation are scoped to each call, and adapters reject configurations belonging to another provider.
- `provider-config.ts`, `event-stream.ts` and `provider-request.ts` contain endpoint policy, SSE parsing and request adapters. `provider-stream/index.ts` coordinates shared stream handling and delegates event decoding to provider-specific modules. Responses API request construction lives in `responses-request.ts`, replay and validation in `responses-replay.ts`, and compatibility exports in `openai-responses.ts`, with stream transport in `responses-stream.ts`, event collection in `responses-stream-events.ts`, and shared definitions in `responses-types.ts`. Responses-specific replay output remains an optional callback on the common stream contract. Existing re-exports are kept for compatibility.
- `tool-definitions.ts` contains side-effect-free local tool descriptions. `tool-turn.ts` defines the executor interface and registry and keeps round and call budgets. `local-tools.ts` and `javascript-tool.ts` implement execution; the latter delegates to the isolated Worker runtime.
- `data-contracts.ts` validates persisted and imported data, `storage.ts` owns IndexedDB transactions, and `branches.ts` owns branch operations. These boundaries must not gain runtime imports that create cycles.

Run `npm run test:architecture` to reject static runtime import cycles. Type-only imports do not create runtime edges. Dynamic imports and non-module side effects still require review. CI also runs the unit, browser, design-token and build checks.

The workspace coordinator, provider stream decoding, and settings view are still sizable. Continue splitting by behavior and contract, with regression tests around reply finalization, cross-tab conflicts, credentials, history consent and updates; do not create duplicate persistence queues or change user data as part of a structural move.
